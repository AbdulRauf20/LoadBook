One-Screen Mobile UI Prototype

LoadBook

A digital version of the handwritten load-distribution notebook, built for Rabnawz, a 45-year-old mobile-load distributor who manages 30–40 shops. No dashboards, no tabs, no analytics — one screen does almost everything.

Persona
Rabnawz, ~45
Basic smartphone user, comfortable with numbers
Design Rule
Do not overdesign
One main daily screen, nothing extra
Core Metaphor
To-do list / table
Checkbox, load sent, received — per shop
Stack
HTML / Tailwind / JS
Maps 1:1 to Flutter widgets

Design System

A tiny, consistent set of tokens — no gradients, no dark mode, no decoration for its own sake.

Color Roles
Primary accent
Buttons, links, focus
Green — Paid
Fully received payments
Yellow/Orange — Partial
Part payment received
Red — Unpaid
Nothing received yet
Checkbox & Buttons
Tap to mark fully paid
Typography & Numbers
Rs. 350,000
Large figures for money
Monday, 3 August
Headings
Body text stays large and high-contrast so it is comfortable to read quickly.

The Main Screen

Almost everything happens here: balance, today's shops, load sent, received, totals, reminders and the daily report.

Today's Notebook Page
Two summary boxes, the shop checklist/table, daily totals, reminders & report

Key Interactions

The few small sheets/dialogs that appear on top of the one main screen — never a new page.

Load Sent — Quick Amounts
5K / 10K / 15K / 20K / 25K or Custom — no typing needed
Received Amount
Load / Received / Remaining always visible; partial payments supported
+ Add Shop
Added once, then appears automatically in every future daily list
Edit / Remove Shop
Tap a shop's name to edit it, or remove it without losing history
Calendar
Jump to any previous day from the date arrows or calendar icon
Send Reminders
One confirmation before messaging every shop with a balance due
No Internet
Plain language, single OK — the notebook itself stays usable offline
Daily Report
Preview totals, then download as PDF or share on WhatsApp
